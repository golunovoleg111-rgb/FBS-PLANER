# FBS Workspace

Браузерный рабочий контур для планирования FBS, физического склада и сборочных заданий. Сервер приложения не требуется; рабочие данные хранятся в IndexedDB браузера, полное состояние можно экспортировать и импортировать.

## Расчёт

- SKU определяется по `barcode`; размер и артикул используются для проверки и отображения.
- Нужны два недельных отчёта WB. Скорость заказов: `70% × последние 7 дней + 30% × предыдущие 7 дней`.
- Выкупы считаются отдельным сигналом. Эффективный спрос равен взвешенной скорости заказов, умноженной на коэффициент выкупа.
- Возвраты не участвуют в потребности.
- FBW можно не учитывать, учитывать полностью или только по выбранным складам.
- Пользователь выбирает SKU и ограничения: число коробов, тип `Любая / MONO / MIX`, максимум изделий.
- В заявку попадают только целые физические `BOX_ID`; виртуальные количества не создаются.
- MIX с лишними компонентами удерживается до ручного подтверждения.
- Оптимизатор учитывает критичность, полезное количество, покрытие SKU, лимиты, бесполезный MIX, число палет и уровень.

## Источники склада

Сайт читает только исходные таблицы и заметки ячеек:

- `1oaf7MiFLdMpOI-syYOaJEeXpIyGRLzkGkUXvlMbJroU`: `BELTANEE STORE - Склад`, `BELTANEE STORE - Склад (второй)`, `кимры`;
- `1Y7vu3v1OoXwNm2dC2qxQMwgENS467L0tv9fWiLxvFVE`: `Лист1`;
- `1ChCILYJikTbjHAmirDThdT6Bn27s06DXIHq6NiQ-FTU`: `Расстановка`.

Каждая физическая колонка исходного Хранения получает стабильный `BOX_ID`. Состав и количество берутся из ячеек этой колонки. Сопоставление с Расстановкой выполняется по складу, составу размеров и количеству; несопоставленный короб сохраняет точную координату исходной колонки и показывается в диагностике.

## Заявки и сборка

Жизненный цикл: `Расчёт → Заморозка → Завершена`. Замороженные короба исключаются из последующих расчётов. Для отсутствующего физического короба доступно ручное удаление с записью в аудит.

При заморозке формируются XLSX, PDF заявки и PDF сборочного задания. Отдельный раздел принимает стандартный Excel WB с колонками D:G и объединяет только точные совпадения `[Наименование, Размер, Цвет, Артикул продавца]`.

## Проверка и разработка

```bash
pnpm test
pnpm build
pnpm dev
```

Тесты покрывают реальные заголовки supplier-goods WB, исходную матрицу хранения, MIX, лимиты, заморозку, экспорт и нагрузку 1500 SKU. Публикация GitHub Pages выполняется текущим workflow из ветки `main`; `base` остаётся `/FBS-PLANER/`.
